# Решения

Решения с пометкой **(пользователь)** согласованы с пользователем 2026-11-10 и не меняются без его согласия. Остальные — технические; менять можно, но с записью здесь.

## D1. Объём v1.0 (пользователь)

- Синхронизация между устройствами — файлами через Google Drive, без своего сервера.
- Android — просмотр и простые правки (узел, текст, напоминание).
- Совместимость с `.xmind` не нужна.
- AI-агент — только через Claude Code (скилл + CLI/MCP). Встроенного агента через API в v1.0 нет.
- Обязательно: drill-down с навигацией вверх и вниз; несколько карт на листе; пользовательские типизированные атрибуты.
- Назначение — личное. Лицензии зависимостей выбирать совместимые с возможной будущей публикацией (MIT/Apache/BSD), чтобы не закрыть этот путь.

## D2. Все изменения — через операции

Документ меняется только списком `Op` через `History`. Одни и те же операции служат UI, undo/redo, агенту и будущему слиянию версий. Альтернатива (иммутабельные снимки документа) отвергнута: дороже по памяти на больших картах и не даёт агенту безопасного API.

## D3. Веб-приложение (PWA) сначала, оболочка потом

Редактор — веб-приложение на TypeScript. Windows: Chrome/Edge + File System Access API. Android: PWA + Google Drive API.

Причины: на машине нет Rust и Android SDK; у Google Drive на Android нет локальной папки, так что доступ через Drive API нужен в любом случае; одна кодовая база без нативной сборки проще для дальнейшей разработки.

Следствия и открытые вопросы:

- PWA на Android требует HTTPS-хостинга статических файлов (например, GitHub Pages). Где размещать — решает пользователь; до этого Android-версия проверяется только локально.
- Для Drive API нужен OAuth-клиент в Google Cloud в тестовом режиме; создаёт пользователь.
- Упаковка в Tauri 2 (Windows, Android) остаётся возможной: весь доступ к платформе идёт через `StorageProvider` и подобные интерфейсы.

## D4. Canvas 2D, не DOM/SVG

Карта рисуется на Canvas с отсечением невидимого; текст редактируется в DOM-поле поверх. DOM/SVG на тысячах узлов не даёт стабильной плавности при панорамировании и масштабировании. Экспорт в SVG/PDF строится из той же раскладки (см. D10).

## D5. Формат файла — один читаемый JSON

`*.ocmap` — обычный JSON, вложения в соседней папке. Zip-контейнер отвергнут: хуже для git, для чтения агентом и для частичной синхронизации Drive.

## D6. Нормализованная модель

Узлы лежат в таблице по id, дерево задаётся `parentId`/`children`, связи — отдельной таблицей. Это упрощает операции, перенос веток и будущий режим графа. Для чтения человеком и агентом есть `oc outline`.

## D7. Drill-down — состояние вида

Вход в под-карту не меняет данные; «настоящее» разделение на листы и файлы — отдельные операции со ссылками между узлами. См. ARCHITECTURE.md.

## D8. Интеграция с GitHub — на стороне агента

Карту кода строит скилл Claude Code по репозиторию; в приложении только ссылки узлов на файлы и URL. Клиента GitHub в приложении нет.

## D9. UI — React, сборка — Vite, тесты ядра — `node --test`

React выбран как самый знакомый любой модели. Ядро не имеет зависимостей и тестируется встроенным раннером Node 24.

## D10. Картинки строятся из раскладки, без общего слоя рисования

Сначала планировался интерфейс `DrawSurface`, который реализовали бы Canvas, SVG и PDF. От него отказались: раскладка (`LayoutResult`) уже содержит всё о положении узлов, а рисование по ней занимает около ста строк на формат. Общий интерфейс пришлось бы подгонять под худший из форматов, и он мешал бы оптимизациям экрана (упрощённая отрисовка при отдалении, отсечение).

Поэтому экранный рендер (`view/render.ts`) и экспорт (`ext/builtin/exportSvg.ts`) — независимые потребители раскладки. Цвета, шрифты и отступы у них общие, из `view/style.ts`. Цена решения: изменение внешнего вида узла вносится в двух местах.

## D11. Производительность (замер 2026-11-11, 5000 узлов, Chromium)

Раскладка 6 мс (первая после открытия — около 120 мс: измеряется текст каждого узла), кадр 3–7 мс на любом масштабе, поиск узла под указателем меньше 0,1 мс. Кэш раскладки по поддеревьям и пространственный индекс не делаем, пока замер на реальных картах не покажет кадр дольше 16 мс.

## D12. Хостинг — GitHub Pages, репозиторий публичный (пользователь, 2026-11-11)

Приложение публикуется на https://mykolamalets.github.io/ObjectConnections/ из ветки `main` workflow `.github/workflows/pages.yml`. Репозиторий сделан публичным: на бесплатном тарифе GitHub Pages работает только для публичных репозиториев. Перед открытием email автора в истории заменён служебным адресом GitHub; в этой папке git настроен на него же.

Следствия: в репозиторий нельзя класть личные данные, карты, ключи и токены. Любой push в `main` сразу публикует новую версию — работать в `dev` и переносить в `main` проверенное.
