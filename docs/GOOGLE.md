# Google: вход, Диск, Календарь

## Настройка в Google Cloud (делает пользователь, один раз)

1. Проект в https://console.cloud.google.com.
2. Включены API: Google Drive API, Google Picker API, Google Calendar API.
3. Экран согласия (Google Auth Platform): External, режим Testing, пользователь добавлен в Test users. Разрешения: `drive.file`, `calendar.events`.
4. OAuth client ID типа Web application. Authorized JavaScript origins: `https://mykolamalets.github.io`, `http://localhost:5173`, `http://localhost:4173`. Redirect URI не нужны. Client secret не используется.
5. API key: ограничен сайтами (те же адреса с `/*`) и только Google Picker API.
6. Номер проекта (Project number) нужен окну выбора файлов как `appId`.

В режиме Testing Google при входе предупреждает, что приложение не проверено, — это ожидаемо.

## Где лежат значения

Три значения — `VITE_GOOGLE_CLIENT_ID`, `VITE_GOOGLE_API_KEY`, `VITE_GOOGLE_APP_ID` — подставляются при сборке:

- локально — файл `packages/app/.env.local` (образец `packages/app/.env.example`; файлы `*.local` не попадают в git);
- на GitHub Pages — переменные репозитория (Settings → Secrets and variables → Actions → Variables), их читает `.github/workflows/pages.yml`.

Они не секретны (видны в коде любой страницы, защищены ограничениями из шагов 4–5), но в репозиторий не кладутся по решению D12. Без `VITE_GOOGLE_CLIENT_ID` приложение собирается без Google Диска.

## Как устроено

- `packages/app/src/ext/google/auth.ts` — общий вход для всех расширений Google. Google Identity Services, модель токенов: токен доступа на час, запрашивается во всплывающем окне Google. Окно открывается только по действию пользователя, поэтому автосохранение и опрос просят токен без окна и получают `SignInRequired`, когда он истёк. Токен хранится только в памяти; повторный вход — одно нажатие, если согласие уже дано.
- `packages/app/src/ext/google/drive.ts` — `StorageProvider` `google.drive`. Разрешение `drive.file`: приложение видит только созданные им файлы и выбранные пользователем в Google Picker. Новые карты кладутся в папку «ObjectConnections» в «Моём диске» (создаётся при первом сохранении, её id запоминается в `localStorage`). Версия файла — поле `version` Drive; внешние изменения проверяются не чаще раза в 10 секунд.
- Если токен истёк: опрос изменений приостанавливается без потери версии, автосохранение показывает «Не сохранено — нажмите «Сохранить»». Нажатие «Сохранить» открывает вход и сохраняет, проверив, не изменился ли файл за это время.
- При нескольких хранилищах «Открыть» и сохранение нового файла спрашивают, куда.

- `packages/app/src/ext/google/calendar.ts` — `ReminderSink` `google.calendar`. Каждое напоминание — событие в основном календаре длиной 15 минут с уведомлением в момент напоминания. В событии в скрытых свойствах (`extendedProperties.private`) лежат `ocDoc` и `ocReminder` — по ним события находятся снова; `calendarEventId` в документ не пишется, поэтому синхронизация не меняет карту и не создаёт шагов отмены.
- Что менять в календаре, решает чистая функция `planCalendarSync` (`state/calendarPlan.ts`, тесты в `packages/app/test/calendarPlan.test.ts`): события создаются только для будущих напоминаний, изменённые обновляются, события удалённых напоминаний удаляются.
- Синхронизирует расширение напоминаний (`ext/builtin/reminders.tsx`): через 2 секунды после изменения напоминаний активной карты (или текста их тем) отправляет карту целиком каждому подключённому календарю.
- Выданные разрешения запоминаются в `localStorage` (`google:granted-scopes`), и любой вход просит их все: открытие файла с Диска заодно продлевает доступ к календарю. Добавление напоминания тоже продлевает доступ, если он был выдан раньше.

## Ограничения

- Файл, положенный на Диск не через приложение (например, Google Drive для компьютера), на телефоне открывается через «Открыть» → «Google Диск» → выбор в Picker; после этого приложение имеет к нему доступ.
- Через час работы без действий пользователя изменения с других устройств перестают подтягиваться до следующего «Сохранить», а календарь — до следующего входа (сохранение на Диск, добавление напоминания, кнопка в панели «Напоминания»).
- Событие появляется в Google Календаре через секунды, но на телефон оно приходит синхронизацией самого приложения «Google Календарь», которая на Android может задерживаться на минуты (особенно в режиме экономии энергии). Если событие пришло позже своего времени, телефон показывает пропущенные уведомления сразу, пачкой. Напоминания ближе 10–15 минут надёжнее ловить в открытом редакторе (проверено пользователем 2026-11-12).
- Две копии одного файла имеют один `id` документа и делят события календаря: правка в одной копии перепишет события другой.
- Напоминания несохранённой карты тоже попадают в календарь; если закрыть её без сохранения, события останутся.
