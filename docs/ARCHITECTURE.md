# Архитектура

## Цели v1.0

- Редактор карт с отзывчивостью XMind 8 на картах в тысячи узлов.
- Windows — полный редактор; Android — просмотр и простые правки.
- Несколько карт на листе, несколько листов в файле, несколько открытых файлов.
- Drill-down (под-карты), слияние, разделение и перенос веток между листами и файлами.
- Пользовательские атрибуты узлов, напоминания, промпты для AI-агента.
- Агент (Claude Code) читает и правит карты через CLI/MCP, без API-ключа в приложении.
- Расширения: хранилища (Google Drive), календарь, импорт/экспорт.

Не входит в v1.0: совместимость с `.xmind`, встроенный агент через API, совместное редактирование в реальном времени, свой сервер.

## Слои

```
┌───────────────────────────────────────────────────────────┐
│ app (React): панели, меню, горячие клавиши, диалоги       │
├───────────────────────────────────────────────────────────┤
│ view: раскладка → рендер (Canvas) → hit-test → жесты      │
├───────────────────────────────────────────────────────────┤
│ extensions: storage / export / import / calendar / panels │
├───────────────────────────────────────────────────────────┤
│ core: Doc, Op, History, Fragment, validate   (без DOM)    │
└───────────────────────────────────────────────────────────┘
        ▲                                   ▲
        │ те же Op                          │ те же Op
   cli / MCP-сервер (Node)            будущая синхронизация
```

Главный принцип: **единственный способ изменить документ — список операций `Op`**. Одни и те же операции используют UI, undo/redo, агент и (в будущем) слияние версий.

## core (`packages/core`)

- `model.ts` — типы `Doc`, `Sheet`, `MapNode`, `Relation`, `AttrDef`.
- `ops.ts` — `applyOp(doc, op)` мутирует документ и возвращает обратные операции.
- `history.ts` — `History`: атомарные транзакции, undo/redo, подписка на изменения.
- `fragment.ts` — вырезание поддерева во фрагмент и вставка в другой документ с новыми id.
- `commands.ts` — составные действия, возвращающие `Op[]` (вынести ветку на лист, влить лист в узел).
- `validate.ts` — проверка инвариантов; используется в тестах, CLI и при открытии файла.

Документ в памяти мутабельный и нормализованный (таблица узлов по id). Это даёт O(1) на операцию и дешёвое undo через обратные операции, без копий документа.

## view (в `packages/app`)

Конвейер кадра:

1. **Раскладка** — чистая функция `layout(doc, sheetId, viewState, measureText) → LayoutResult` (прямоугольники узлов, пути соединений). Кэш по поддеревьям: пересчитывается только ветка, размеры которой изменились, и её предки.
2. **Рендер** — рисование на Canvas 2D через интерфейс `DrawSurface` с отсечением по видимой области. Тот же интерфейс реализуют SVG и PDF для экспорта.
3. **Hit-test** — поиск узла под указателем по `LayoutResult` (пространственный индекс по строкам/прямоугольникам).
4. **Редактирование текста** — DOM-`textarea` поверх Canvas на месте узла.

`ViewState` (масштаб, смещение, выделение, стек drill-down) не входит в историю undo и хранится отдельно от содержимого (см. FORMAT.md).

Структуры раскладки v1.0: карта (ветки в обе стороны), логическая схема вправо, дерево, оргсхема. Каждая структура — функция с одной сигнатурой, зарегистрированная по id; узел может переопределить структуру своего поддерева.

### Drill-down

Drill-down — это состояние вида, а не данных: `viewState.focusPath` хранит стек id узлов. Раскладка строится от последнего узла стека как от корня; сверху показывается навигационная цепочка для возврата на уровень выше. Узел, у которого есть «настоящая» под-карта на другом листе или в другом файле, хранит ссылку `link` типа `node`; переход по ней и обратно — та же навигация.

## Платформы и хранение

Интерфейс `StorageProvider` (list/read/write/watch) с реализациями:

- **LocalFs (Windows)** — File System Access API в Chrome/Edge; файлы лежат в папке Google Drive for Desktop и синхронизируются ею.
- **GoogleDrive (Android)** — Drive REST API, потому что на Android у Google Drive нет локальной папки.

Приложение — PWA: на Windows открывается в Edge/Chrome и ставится как приложение, на Android ставится из Chrome. Упаковка в Tauri — отдельная необязательная задача (см. решение D3).

Конфликты синхронизации в v1.0 решаются на уровне файла: при расхождении версий приложение предлагает открыть обе и слить листы вручную. Поля `modified` у узлов заложены для будущего автоматического слияния.

## Агентная часть (`packages/cli`)

- CLI `oc`: `outline` (дерево текстом с id), `find`, `get`, `prompts` (очередь промптов), `add` (ветка из текста с отступами), `set`, `move`, `remove`, `apply` (произвольные `Op[]` из JSON), `validate`. Запись атомарная: временный файл и переименование.
- Редактор раз в две секунды сверяет версию открытого файла и перечитывает его, если несохранённых правок нет; так изменения агента появляются на экране сами.
- MCP-сервер — тонкая обёртка над теми же функциями.
- Скилл для Claude Code: описание формата, правила работы с картой, рецепты (карта кода по репозиторию, выполнение промптов в узлах).

Агент никогда не редактирует JSON файла руками — только через `oc apply`, что гарантирует инварианты.

Промпт в узле: `prompt = { text, status, scope }`. Пользователь ставит статус `queued`, агент по команде обрабатывает очередь, достраивает ветку и ставит `done`.

## Расширения

Расширение — модуль `{ id, activate(ctx) }`. Через `ctx` оно регистрирует:

- команды и пункты меню;
- импортёры и экспортёры (FreeMind, Markdown, PDF, Word);
- провайдеры хранилищ;
- типы атрибутов и боковые панели;
- обработчики напоминаний (Google Calendar).

Встроенные функции пишутся как такие же расширения, чтобы API был проверен собственным кодом. Данные расширений в документе лежат в поле `ext` под своим пространством имён.

## Граф в будущем

Модель уже содержит всё нужное для графа объектов: несколько независимых корней на листе и типизированные связи `Relation` между любыми узлами. Режим графа — это другая раскладка и другой набор жестов поверх той же модели, без смены формата.
