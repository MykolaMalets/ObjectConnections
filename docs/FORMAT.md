# Формат данных и операции

Источник истины по типам — `packages/core/src/model.ts` и `ops.ts`. Этот документ объясняет смысл и инварианты.

## Файл

- Один файл карты — `*.ocmap`: JSON в UTF-8, с отступами в 1 пробел и стабильным порядком ключей (удобно для git и для Drive).
- Вложения (картинки) — в соседней папке `<имя файла>.assets/`, в документе хранится относительный путь.
- Состояние вида (масштаб, выделение, drill-down) в файл карты не пишется; оно хранится локально на устройстве по `doc.id`.

## Документ

```
Doc
 ├─ format: "ocmap", version: 1, id, title
 ├─ sheets: Sheet[]              порядок листов
 ├─ nodes: { id → MapNode }      все узлы всех листов
 ├─ relations: { id → Relation } связи между любыми узлами
 ├─ attrDefs: { id → AttrDef }   определения пользовательских атрибутов
 └─ ext: { namespace → данные }  данные расширений
```

### Sheet

`{ id, title, rootIds, structure?, ext? }`. `rootIds` — корни карт на листе: первый — центральная тема, остальные — независимые карты (плавающие темы) со своим `position`.

### MapNode

| Поле | Смысл |
|---|---|
| `id`, `parentId`, `children` | Положение в дереве. У корня `parentId = null`. |
| `text` | Заголовок узла. |
| `notes` | Заметка в Markdown. |
| `labels`, `markers` | Метки и id маркеров. |
| `attrs` | Значения атрибутов: `{ attrDefId → значение }`. |
| `link` | Ссылка: `url`, `file` (относительный путь), `node` (id узла, в т.ч. в другом файле: `docId` + `path`). |
| `prompt` | `{ text, status: draft \| queued \| running \| done \| error, scope: node \| subtree \| sheet, message? }`. |
| `reminders` | `[{ id, at (ISO 8601), text?, calendarEventId? }]`. |
| `collapsed` | Свёрнута ли ветка. |
| `structure` | Раскладка поддерева, если отличается от унаследованной. |
| `position` | Координаты для корней и вручную сдвинутых узлов. |
| `style` | Переопределения оформления. |
| `modified` | Время последней правки (ISO 8601), проставляет `History`. |
| `ext` | Данные расширений. |

Зарезервировано на v1.1: границы и сводки (диапазоны детей у родителя), выноски.

### Relation

`{ id, from, to, text?, type?, style?, ext? }` — направленная связь между двумя любыми узлами. `type` — произвольная строка; в режиме графа это тип связи.

### AttrDef

`{ id, name, type: text | number | date | bool | url | select | multiselect, options?, ext? }`.

## Инварианты (проверяет `validate`)

1. Каждый id в `children` существует, и у ребёнка `parentId` указывает на этого родителя.
2. Каждый узел с `parentId = null` входит ровно в один `sheet.rootIds`; других узлов в `rootIds` нет.
3. Дерево без циклов; каждый узел достижим от какого-то корня.
4. Концы каждой связи существуют.
5. Ключи `attrs` существуют в `attrDefs`.
6. Все id уникальны в пределах документа (узлы, листы, связи, атрибуты — общее пространство).

## Операции

Все операции — простые JSON-объекты с полем `t`. `applyOp` сначала проверяет предусловия и бросает `OpError`, ничего не изменив; затем мутирует документ и возвращает список обратных операций.

| Операция | Действие |
|---|---|
| `insertSubtree { nodes, rootId, parentId, sheetId?, index?, relations? }` | Вставить поддерево (в т.ч. один узел). При `parentId = null` нужен `sheetId` — узел станет корнем на листе. |
| `removeSubtree { id }` | Удалить узел с потомками и все связи, которые их касаются. |
| `moveNode { id, parentId, sheetId?, index? }` | Перенести поддерево к другому родителю, на другой лист или изменить порядок. |
| `patchNode { id, patch }` | Изменить поля узла. `null` в `patch` удаляет поле. Нельзя менять `id`, `parentId`, `children`, `attrs`. |
| `setAttr { id, defId, value }` | Задать значение атрибута; `null` удаляет. |
| `putAttrDef { def }` / `removeAttrDef { id }` | Создать/изменить и удалить определение атрибута (значения у узлов тоже удаляются). |
| `insertSheet { sheet, index? }` / `removeSheet { id }` | Добавить пустой лист; удалить пустой лист. |
| `patchSheet { id, patch }` | Изменить `title`, `structure`, `ext`. |
| `putRelation { relation }` / `removeRelation { id }` | Создать/изменить и удалить связь. |
| `patchDoc { patch }` | Изменить `title`, `ext`. |

`index` — позиция в списке назначения после того, как узел убран со старого места; без `index` — в конец.

## Составные действия (`commands.ts`)

Функции, которые по текущему документу строят `Op[]` для одной транзакции:

- `opsExtractToSheet(doc, nodeId, { leaveLink })` — вынести ветку на новый лист; на старом месте по желанию остаётся узел-ссылка.
- `opsMergeSheetInto(doc, sheetId, targetNodeId)` — все карты листа становятся ветками узла, лист удаляется.

## Фрагменты (`fragment.ts`)

`extractFragment(doc, nodeId)` возвращает самодостаточный `Fragment` (узлы, внутренние связи, использованные определения атрибутов). `opsImportFragment(doc, fragment, target)` строит операции вставки с новыми id. На этом построены копирование, перенос ветки в другой файл и разделение файла; формат буфера обмена — тот же `Fragment` в JSON.

## Идентификаторы

12 символов base62 (`newId()`), генерируются на клиенте. При вставке фрагмента id всегда пересоздаются.
